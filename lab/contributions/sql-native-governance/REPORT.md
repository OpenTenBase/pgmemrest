# 课后作业 B · pgmemrest SQL 原生记忆治理

## 目标与设计

pgmemrest 的上游服务通过 RPC 添加或检索记忆。这个原型补充一个数据库写入入口，由触发器检查同一用户下的结构化事实键，再决定新增、更新、撤回或跳过。普通服务账号只获准提交输入和读取动作。维护账号执行衰减归档和精确去重，审计员只读。归档数据保留在原记录中，活动查询通过视图过滤。 [上游记忆服务](https://github.com/OpenTenBase/pgmemrest/tree/main/openclaw_plugin/docker) · [安装与接入](README.md)

记忆保留分按最近一次有效写入的时间指数衰减。以 30 天为半衰期，60 天后分数达到 0.25，定时任务分批归档达到该阈值的记录。精确去重用 `row_number()` 对同一用户、同一类别的相同内容排名，保留最新版本，时间并列时按事实键选定保留项。审计记录变更动作、原始会话账号、用户和事实键，跟随记忆变更一起提交。 [PostgreSQL 窗口函数](https://www.postgresql.org/docs/16/functions-window.html) · [PostgreSQL 触发器](https://www.postgresql.org/docs/16/sql-createtrigger.html)

## 验证结果

在独立运行的 PostgreSQL 16.16 实例中，用合成记忆运行 `install.sql` 与 `test.sql`。测试里先写入 8 条带标签的种子记录，其中 6 条带人工回填的时间，用于覆盖归档阈值和压缩顺序。

| 验证项 | 实测结果 |
| --- | --- |
| 写入决策 | 同一事实依次返回 `ADD → NOOP → UPDATE → DELETE → NOOP → ADD`。重复输入保留原时间戳，撤回后记录退出活动视图。 |
| 衰减归档 | 批量上限设为 1，两次各归档 1 条，第三次返回 0。60 天边界样例归档，59 天样例保持活动。 |
| 记忆压缩 | 归档 2 条重复记忆，保留最新条目，重复执行返回 0。其他用户的同内容和当前用户不同类别的同内容均保留。 |
| 审计与回滚 | 审计计数为 `ADD 10 / UPDATE 1 / DELETE 1 / NOOP 2 / ARCHIVE 2 / COMPRESS 2`，包含种子记录。已回滚写入的记忆、回执及审计事件均未保留。 |
| 数据库权限 | 写入角色直接修改基表、停止审计触发器、清空审计、伪造决策和调用维护程序均失败。维护角色不能删除审计，审计角色不能修改审计。回执留存动作和时间。 |

## OpenTenBase 兼容性实测

用课程虚拟机里安装目录为 5.21.8 的分布式 OpenTenBase 实测，数据库报告 `OpenTenBase_v5.0`（提交 `b612d77cb`）。模式、表和普通表触发器均能创建。低权限角色通过 `SET ROLE` 写入时，触发器内部的分布式语句返回 `42501`，提示不能在 `SECURITY DEFINER` 函数中设置 `session_authorization`。使用独立低权限账号登录再次测试，也在切换到所有者的会话授权时返回了 `42501`。测试结束后清理了临时数据库和角色。

本作业的验收目标为社区 PostgreSQL。定时任务配置已给出，实测覆盖它调用的归档函数。接入 pgmemrest 时需要把服务里的写入路由接到本原型的 `inbox`，并由服务提供经过认证的用户标识和结构化事实键。
